# Ngel 初始化

插件根目录为本文件所在技能目录的上两级。读取根目录 references/requirements.md，使用 assets/config 和 assets/knowledge 的模板；插件安装目录只读，业务数据写入用户指定工作区。

用户未指定工作区时使用当前项目下 ngel-workspace，先说明这个默认位置。执行根目录 scripts/workspace.py init --workspace <绝对目录>。脚本只创建不存在的文件；已有配置不覆盖。随后运行同一脚本的 check 子命令。

## 自动询问与保存

初始化后自动执行 `python -X utf8 <插件根目录>/scripts/onboarding.py status --workspace <绝对目录>`。不要求用户一次填完整张表。先检查宿主已授权连接器和已提供的文件，能可靠读取的字段先提取为待确认答案；不得扫描无关邮箱、日历或将当前个人账号推定为 Ngel 业务账号。

按输出 next_questions 每批最多三问，用宿主可用的异步提问工具；没有该工具则在聊天中询问。匹配用户语言使用 zh-CN 或 en 文案。用户回答后，将单个字段保存到工作区内 UTF-8 答案文件，格式为 {"id":"字段ID","value":值}，再执行 `onboarding.py apply --workspace <目录> --answer-file <文件>`。成功后删除本轮临时答案文件，保留正式业务配置。参数通过文件传入，避免 shell 转义损坏中文或暴露敏感值。

platform_accounts 值为 [{"platform":"Instagram","account":"账号链接"}]；boss_delivery 为 {"channel":"渠道","recipient":"准确收件人"}；reference_videos 和 script_languages 是字符串数组；其余字段为字符串。只保存用户实际提供或明确确认的答案。不要填写密码、令牌、支付卡，账号授权由宿主官方登录流程处理。

每次保存后再次读取 status，只询问剩余字段。用户暂不提供则执行 `onboarding.py defer --workspace <目录> --field <字段ID>`；延期项仍是上线缺口，但后续不重复追问，用户愿意补齐时用 resume 恢复。资料来源尚待接入、填写“没有”或“需要新建”只表示已答复，不能算系统就绪。业务核验和平台授权仍独立执行。

授权不能由收集答案自动升级，onboarding 不修改外部发送或预约权限。时区答案经校验后同步存入规则和 schedules 文件；有已启用计划时拒绝修改，须先暂停并核对宿主任务时区，不能仅依赖 cron 文本。会话中已答字段直接保存，避免重复问；每次启用前运行 workspace.py check --strict 并核验实际系统。退出码 1 表示配置错误，2 表示缺少上线资料；0 也只代表离线配置就绪，不证明外部连接已授权或通过验证。

确认首批平台及账号、参考博主或视频、数据访问方式、老板渠道和收件人、脚本语言、业务时区、员工班次和服务时长、权威预约系统。可分批配置，缺什么只暂停对应功能，不反复索取已提供信息。默认新加坡时区仍需确认。

输出可用能力及缺口。配置中的 permission 布尔值是操作约束，不是访问凭据或平台授权。没有实际服务就不能宣称自动化已启用。没有内置 MCP 或平台 API，不虚构工具名；发现宿主可用连接器后核验实际能力。

用户要求启用定时工作时，优先发现宿主 automation_update 工具并遵守其真实 schema；没有调度工具则提供待配置状态，不模拟创建成功。每半小时全天检查新消息，晚 20:00 交付五篇脚本及复盘，使用已确认时区。晚间生成任务需提前运行。文件里的 cron 只是设计值，不是运行回执；安装插件本身不创建定时任务。

后续路由：内容工作使用 ngel-content；客户及预约使用 ngel-service；知识核验和持久记忆使用 ngel-governance。
