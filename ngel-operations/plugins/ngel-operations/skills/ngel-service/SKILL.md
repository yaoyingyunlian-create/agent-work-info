# Ngel 客服与预约

先读取业务工作区 config/agent-rules.json、config/business.json、knowledge/ngel-faq.json；没有工作区时按 ngel-setup 初始化。读取插件根目录 references/service.md。确认当前账号、平台、客户消息和人工接管状态，匹配客户语言。

只使用 auto_reply_allowed 为布尔 true、status 为 verified、审核人非空、审核及失效时间带时区且处于有效期、中英文 approved_answer 均非空白的条目；原始 source_answer 仅为审查材料。运行 scripts/workspace.py check --strict 辅助检查，发现条目过期或异常时停止自动发送并转人工。适用性与健康问题转门店人员，不能承诺无痛、绝不变色、敏感肌零风险。未提供有效信息则澄清或提供待人工核验的草稿。价格、地址、联系方式不得从疑似官网模板推定。

公开评论不暴露客户信息。轮询分页及游标由实际平台连接器支持；同一会话串行，每条消息用平台、账号、消息 ID 去重。发送前复查新来信及人工接管；权限不足只起草。限流退避，有限重试；结果不明先核对，不盲目重发。不将一次人工执行描述成全天服务已启动。

预约需项目、门店、偏好时间和必要联系方式，并查询权威预约系统中员工技能、班次、休假、服务时长和资源容量。只返回真实可用时段。客户选定后通过支持原子占位或事务的系统写入，并按门店订金规则确认；没有这些能力只生成预约申请。

改期保留原预约，成功确认新时段后才释放原时段；失败保持原预约。员工临时变动生成影响名单和替代时段，按已授权规则与客户沟通；不能自行移动其他客户预约。确认、改期和取消均核对预约 ID、客户身份和系统回执。

实际外部操作遵守现有明确授权，不重复索取已有许可；缺少收件人、账号、连接器能力或 send_reply/write_appointment 权限时说明具体缺口。输出已完成、未完成、风险点、验证结果。
