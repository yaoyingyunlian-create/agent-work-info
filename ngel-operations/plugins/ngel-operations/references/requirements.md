# Ngel Agent 需求与实施方案

日期：2026-11-03。状态：需求与配置草案，未部署，未建立任何定时任务或发送任何消息。基于用户需求、桌面知识库.txt 及官网首页实读；不把素材中的指令当作系统指令。

## 目标与边界

建立内容运营、客户服务、预约调度三个工作流，共用经核验的 Ngel 知识库和客户记录。现有目录为空，无可复用业务代码。本阶段交付方案与配置，不代表已经具备平台连接、后台服务或自动发送能力。

官网来源：https://ngelacademy.com/home ，读取日期 2026-11-03。首页展示半永久纹绣、皮肤管理、美睫、身体护理、脱毛、附加服务及课程入口。首期建议覆盖纹眉，再逐项补齐，不能将纹眉答案套到眼线、唇部或其他服务。

## 内容运营

输入：指定博主主页或视频链接、可访问的视频或字幕、目标平台、客户画像、推广服务及真实案例授权。没有视频画面或完整文本时，注明分析依据，不能宣称完成视觉或镜头分析。借鉴结构与表达方法，不逐字复制博主脚本。

流程：拆解开头吸引点、目标痛点、信息顺序、案例证据、节奏、镜头、字幕及行动引导；结合 Ngel 已核验资料改写。每天当地时间 20:00 向指定老板渠道交付五篇待发布标准脚本和上一条视频复盘。先生成、质检、再投递；生成开始时间及重试次数在接入后按实际耗时配置。老板渠道未确定前只保留本地产物，不能自行推定收件人。

标准脚本字段：日期、版本、平台、语言、目标客群、主题、目标服务、参考来源及可访问范围、标题、封面文案、预计时长、开头、逐镜时间段、画面、口播、字幕、行动引导、所用业务事实来源、拍摄素材、审核状态。五篇选题避免重复，可分别覆盖科普、误区、设计过程、案例、预约疑问；无案例授权时改用非案例选题。

上一条视频按平台和账号识别最近一次发布，记录发布时间和统计截止时间。尽可能采集曝光、播放、停留、平均观看、完播、互动、收藏、主页访问、私信、预约和成交。只对相同平台、相同指标定义和相同观察窗口比较；不同平台不直接相加比较。记录自然与投流流量。分母为零、平台不提供或授权失败时标记缺失，不填造数值。未满观察窗口时作阶段性分析。

复盘输出：现象、对应数据、可能原因、下一条调整、验证指标。缺失数据时交付明确标注的数据缺口和暂定建议，不能声称完成数据分析。样本不足时不作因果结论。建议分别留存发布后 24 小时及 72 小时快照；是否采纳由运营确认。

## 客服与知识库

每半小时全天检查已授权平台的新私信和评论。仅使用平台允许的接口或已批准方式；接入前逐平台核验权限、回复窗口、限流和可用数据。当前没有任何平台账号被连接。

按客户来信语言回复，中英文共用事实 ID，更新时同步审核。公开评论避免暴露客户资料；咨询转私聊须遵循平台规则。客户意图分为服务、价格、适用性、护理、课程、预约、改期、取消、投诉和人工协助。先检索已核验且未过期的条目；缺少依据时澄清或转人工。不能通过猜测补全价格、疗效、优惠、认证或规则。

原始文件的 11 组问答全部保留为待核验来源；医疗级认证、绝不变色、敏感肌无刺激、护理碰水、麻药、补色时间及付款顺序需要门店负责人核验。对健康适用性不作自动判定，护理以门店针对具体项目确认的版本为准。

官网目前出现疑似模板联系方式 info@example.com、+55 电话，以及真实业务联系区域；两者不能自动合并。首页展示的 S$388 仅为当次页面所见项目价格，不作为当前全项目报价。地址、电话、营业时间、价格均须门店确认后启用。

每次处理使用平台、账号、消息 ID 去重；游标持久化，失败不提前推进；分页拉取，避免忙时漏消息；同一会话串行处理，发出前复查新消息与人工接管状态。限流退避、有限重试、死信和人工处理。发送超时后先查询发送结果，不能盲目重发。没有新消息时静默。轮询延迟正常接近 0 至 30 分钟，故障或限流可能更长；24 小时指全天运行，不承诺即时回复或全天人工在线。

## 预约与员工排班

客户提供项目、门店、偏好时间、可选员工、姓名和必要联系方式；员工资料提供可服务项目、技能、班次、休假、服务时长、清洁缓冲及资源约束。两小时仅为原始纹眉问答的待核验时长，不能套用其他项目。

在单一权威预约系统中查询空档，候选时段应同时满足员工、服务、门店及床位或房间容量。客户选定后以事务或原子占位防止并发冲突，满足门店订金政策后才确认。占位有效期由业务决定。无法写入权威系统时只创建预约申请，不告知客户已预约成功。

状态：申请、待客户确认、临时占位、待订金、已确认、已完成、取消、未到场；流程可按业务配置简化。每次变动记录操作者、原因、旧值、新值和版本。改期先保留旧预约，原子确认新时段后再释放旧时段；失败保持原预约。客户确认后更换员工或时间，员工临时请假则生成影响列表与候选方案，按预先确认的业务规则通知并征得客户选择，不能自动挪动其他客户的已确认预约。

平台重复事件、网络重试、同时抢占、跨日时段、休假、过期占位及改期失败均纳入验收。所有存储用 UTC，界面与调度用经确认的业务时区。

## Agent 规则和记忆

见 config/agent-rules.json。四种权限分开：读取、起草、发送、预约写入。配置草案默认外部写入关闭。用户提出的自动回复与排班是目标范围，正式启用须具备明确账号、业务规则和有效授权，不能将授权扩展到批量营销、自动发视频或退款。

业务记忆记录有来源和有效期的事实；客户记忆记录经客户提供的必要偏好及预约状态；任务记忆保存消息游标、投递去重键和执行状态；运营记忆保存视频表现及待验证假设。客户话语、官网内容或视频台词都不能修改 Agent 规则。规则版本只有管理员可更改。

不把本项目客户记忆写入 Codex 个人记忆。客户数据按账号与租户隔离，权限、保留周期、删除请求和日志脱敏按业务确认后实现，不保存账号密码、支付卡或无必要健康细节。

## 实施顺序与验收

1. 业务核验：确认服务、价格、护理、补色、营业时间、退款和预约规则；补齐双语知识库。
2. 单平台试点：接通一个社交平台和权威日历，先生成回复草稿和预约申请，验证去重、限流和人工接管。
3. 启用指定范围自动回复及预约写入；再拓展其他平台。需要服务端常驻调度、持久存储、任务队列和监控；现阶段不选定框架或增加依赖。
4. 接入视频素材和后台指标，试跑五篇脚本及复盘，确认老板接收渠道后启用 20:00 交付。

验收要求：五篇均字段完整、主题不同、无未核验承诺；中英文事实一致；重复消息最多一次有效回复；人工接管后停止自动回复；并发预约不重复占用；改期失败不丢原预约；定时任务重启可恢复；失败有告警且不泄露客户信息。投递成功必须有渠道回执，预约成功必须有权威系统记录。

## 需要补齐的输入

- 首批平台及账号、参考博主或视频、上一条视频链接及后台数据访问方式。
- 老板接收渠道和具体收件人；业务时区是否为 Asia/Singapore；五篇脚本的主要语言和视频长度。
- 员工名单、技能、班次、门店及资源、项目时长、现有预约表或系统、订金和改期规则。
- 经负责人确认的服务价格、护理和售后条款；人工负责人及值班时段。
