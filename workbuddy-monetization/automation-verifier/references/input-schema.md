# 输入契约 v1

根对象：`as_of` 为带时区 ISO 8601 时间；`days` 为1至31整数，默认7；`coverage_confirmed` 仅在用户确认任务清单、应执行时段与例外完整后设为 true，缺省 false；`tasks` 为数组。覆盖声明不是脚本独立证明。

每个任务：唯一 `id`、`name`、`runs` 数组。每次应执行实例：唯一 `id`、`start`、`due`（均含时区，start <= due）；`claimed_status` 为 success / failed / unknown（默认 unknown）；可选 `claim_source` 为运行导出路径或用户说明出处，不含令牌。success 必须提供非空 claim_source；脚本只记录出处，不独立认证声明。可选 `artifact` 为本次产出路径，相对路径基于输入JSON所在目录，必须逐次保存历史快照。

每次的 `checks`：

- `mtime` 必须 true：检查文件最后修改时间落在 start..due 内；mtime 只能证明文件元数据，不能证明内容来源和历史状态。共享/覆盖文件不能还原过去，不能拿今天文件证明前几天成功。
- `format`：csv / json / text。CSV 使用 UTF-8（支持BOM）、逗号分隔、有表头；JSON 为对象数组；text 每个非空行视为一行。
- `min_rows`：非负整数，必填。CSV不计表头，JSON按数组元素数，text按非空行数。0仅在用户确认允许空产出时使用。
- `required_fields`：CSV/JSON 顶层字段名数组；每行均需存在且非空，纯空白字符串为空；数字0和false不算空。text只支持空数组。
- 可选 `data_time_field`：CSV/JSON 中每行的带时区 ISO 8601 业务时间，须在 start..due 内。历史/累计报表不适用此约束时不要配置；需要其他业务范围时先由用户明确口径并人工核验，不擅自套用运行时间。

无完整checks即需人工；空JSON数组或仅有CSV表头时仍验证字段结构（空JSON无法证明字段结构）。不支持 XLSX、PDF、压缩包、远程URL、SQL和自然语言内容质量检查，先转为可核查快照或人工检查。不执行cron，不读取任务配置API，不推断本机时区，不联网。

一个产出路径如果被多个实例复用，全部标记历史不可还原，不能判绿，即便mtime看似有效。需为每次运行提供独立快照。若文件缺失可判定明确失败；权限错误、编码损坏、格式不支持属于证据不可判定。格式正确但行数或字段不达标属于明确失败。

输入目录也可存放报告之外的资料；报告目录必须是全新路径，且不能包含输入或任何产出路径。脚本不修改源文件。输入在检查期间可能变化，脚本检测大小/mtime变化并将该次检查转为需人工；这不是文件系统事务快照。

使用 `assets/template.json` 填入真实任务。应执行时段需要包含关机、未启动、无日志的情况；不完整清单的报告必须标记“覆盖未确认”。
