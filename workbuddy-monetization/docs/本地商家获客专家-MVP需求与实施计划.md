# WorkBuddy 本地商家获客专家（美业）MVP

## 1. 立项结论

首期聚焦 **美业单店经营者**，交付可直接执行的“7 天到店获客计划”。

不做泛营销咨询，也不承诺客流、营业额或转化结果。智能体基于商家填写的信息给出策略、素材和复盘建议；实际效果受门店服务、地段、预算、平台流量和执行质量影响。

## 2. 目标用户与核心问题

| 项目 | 定义 |
| --- | --- |
| 目标用户 | 美甲、美睫、皮肤管理、美发等线下单店店主或运营人员 |
| 典型阶段 | 有服务和门店，但缺少稳定线上内容、到店转化和老客复购机制 |
| 核心需求 | 快速得到一套可执行、可复制、符合自身预算的获客行动方案 |
| 主要渠道 | 抖音、小红书、微信朋友圈、社群、团购平台 |

## 3. MVP 范围

### 3.1 必做

1. 结构化商家诊断问卷。
2. 基于问卷生成门店诊断和优先级。
3. 生成 7 天获客执行排期。
4. 生成活动方案、基础毛利测算和风险提示。
5. 生成渠道内容素材：短视频脚本、小红书笔记、朋友圈、社群邀约。
6. 生成到店接待、成交、加微信和复购唤醒话术。
7. 生成每日复盘表，并根据录入数据提供下一步建议。
8. 保存匿名化门店档案、方案和复盘记录。

### 3.2 首期不做

- 自动发布到抖音、小红书、美团或微信。
- 直接连接支付、团购、广告投放或 CRM。
- 跨行业专用知识库与跨门店团队协作。
- 实际营业额归因、投放自动优化或效果承诺。
- 收集店主真实姓名、身份证、精确住址、顾客个人信息。

## 4. 用户流程

```text
创建匿名门店档案
    → 填写经营诊断问卷
    → 生成 7 天获客计划
    → 每天查看任务并复制营销素材
    → 录入曝光、咨询、到店、成交、加微等汇总数据
    → 获得当天复盘和次日调整建议
```

## 5. 输入设计

### 5.1 门店档案（最小字段）

- 门店昵称（非真实姓名）
- 细分业态：美甲 / 美睫 / 皮肤管理 / 美发 / 其他美业
- 城市级别、商圈类型（仅粗粒度）
- 开业阶段：筹备 / 新店 / 稳定经营 / 客流下滑
- 客单价区间、主推项目、单次服务时长
- 日均到店量、可接待上限、现有会员或私域规模（可选）
- 可用渠道、每周可投入预算和可执行人力
- 当前最大问题：缺曝光 / 缺咨询 / 到店低 / 成交低 / 复购低

### 5.2 每日复盘输入

- 内容发布数、曝光/浏览、咨询、预约、到店、成交、加微信数量
- 当日活动成本、优惠核销量、顾客反馈摘要
- 执行障碍（可选）

所有数值为门店汇总数据；不得输入顾客姓名、电话、微信号或订单明细。

## 6. 输出交付标准

### 6.1 门店诊断

必须包含：

- 现状摘要和最优先的 1 至 3 个问题。
- 可控事项与依赖外部条件的事项分开说明。
- 先执行的动作、预期观察指标和风险提示。

### 6.2 7 天计划

每天明确列出：目标、准备物料、渠道动作、可复制文案/脚本、到店承接动作、需记录的指标和复盘问题。

### 6.3 活动与测算

活动方案至少给出：目标人群、主推服务、原价、活动价、可承受的单次让利、名额或有效期、核销规则、升级路径和风险。

基础毛利计算：

```text
单次活动毛利 = 活动实收 - 变动服务成本 - 平台/渠道分摊成本
活动最低成交数 = 活动固定成本 ÷ 单次活动毛利
```

当单次活动毛利小于等于零时，必须阻止“保本”表述，并建议调整价格、服务组合或成本。

### 6.4 复盘建议

- 优先用漏斗定位问题：曝光 → 咨询 → 预约 → 到店 → 成交 → 加微 → 复购。
- 数据不足时明确说明“样本不足，不下结论”。
- 每次最多给出 3 项下一步动作，避免增加店员执行负担。

## 7. 计费与权限建议

| 层级 | 内容 |
| --- | --- |
| 免费体验 | 一次基础诊断、1 条渠道文案预览 |
| 单次方案 | 完整 7 天计划、活动测算、素材包和复盘模板 |
| 订阅陪跑 | 每周计划、持续素材、每日复盘建议、历史对比 |

价格、试用次数、权益额度、模型选择和输出长度必须后台可配置，不写死在专家业务逻辑中。

## 8. 配置与技术约束

沿用配置优先原则：

- 专家介绍、问卷、渠道模板、行业规则、提示词版本、模型能力、计费权益和价格放在配置中。
- 使用通用的能力、协议和计费配置表达差异；只有确实缺少可复用能力时才补通用代码。
- 后台保存后立即生效，并失效公共配置缓存；不增加发布步骤。
- 门店档案与复盘数据按门店隔离；默认只保存最少必要的汇总经营数据。

## 9. 验收标准

1. 新用户可在一次完整问卷后获得结构完整的 7 天计划。
2. 每天任务均包含渠道、素材、承接动作和指标。
3. 活动测算可发现单次毛利不为正的方案并给出风险提示。
4. 复盘只基于已输入的汇总数据；数据不足时不伪造结论。
5. 所有面向用户的字段和输出同时具备中文文案；如存在英文管理端字段，需同步维护。
6. 配置更新无需修改单个行业的业务分支代码即可生效。

## 10. 开发拆分

### P0：可演示闭环

1. 创建 `local-business-acquisition` 专家技能包骨架。
2. 实现匿名门店档案和经营问卷。
3. 实现固定结构的 7 天计划、活动测算和素材生成。
4. 实现每日汇总复盘和漏斗建议。
5. 编写覆盖正常、数据不足和负毛利场景的自动化测试。

### P1：提升付费价值

1. 加入细分业态模板和品牌语气配置。
2. 加入历史计划对比和周报。
3. 加入权益额度与订阅计费配置。

### P2：平台化能力

1. 接入外部内容/团购/CRM 工具（需逐项授权）。
2. 支持多门店与员工协作。
3. 扩展餐饮、教培、健身等行业模板。
